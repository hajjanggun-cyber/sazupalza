## 1. 최종 판단

현재 사이트는 애드센스 심사를 통과한 상태로 보이며, 기본적인 승인 신호는 들어가 있다.

- `app/[locale]/layout.tsx`에 `google-adsense-account` 메타 태그가 있음.
- `app/[locale]/layout.tsx`에서 `pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-2524681039359256` 스크립트를 로드함.
- `public/ads.txt`에 `google.com, pub-2524681039359256, DIRECT, f08c47fec0942fa0`가 있음.
- `robots.ts`에서 `Mediapartners-Google`을 별도로 허용하고 있음.

따라서 문제의 핵심은 "승인 여부"가 아니라, 글 상단 광고가 실제로 상단 광고 후보로 평가받기 어려운 구조와, 광고가 늦게 채워질 때 사이트 쪽에서 너무 빨리 숨겨버리는 구현 방식에 있다.

가장 중요한 문제는 다음 4개다.

1. 조치 완료: 글 상세 페이지의 상단 광고를 목차 뒤에서 대표 이미지 바로 아래로 이동함.
2. 조치 완료: 광고 컴포넌트가 광고 iframe이 2.5초 안에 생기지 않으면 광고 영역을 숨기던 로직은 제거함.
3. 조치 완료: `AdSense` 컴포넌트가 전달받은 `slot` 값을 사용할 수 있게 수정함. 단, 현재 placeholder slot 값들은 기존 실광고 slot으로 fallback 처리함.
4. 조치 확인: 한국어 광고 라벨은 현재 `광고`로 정상 표시됨.

## 2. 공식 기준으로 본 전제

애드센스 자동 광고나 디스플레이 광고는 "상단에 항상 걸리는 구조"가 아니다. Google은 페이지 레이아웃, 콘텐츠 양, 사용자의 화면, 광고 수요, 정책 상태, 광고 단위의 성과, 사용자 경험을 함께 보고 게재 위치와 채움 여부를 결정한다.

특히 공식 문서 기준으로 다음을 전제로 봐야 한다.

- 자동 광고는 사이트를 스캔한 뒤 광고가 잘 작동하고 사용자 경험이 좋을 만한 위치에 자동으로 배치된다.
- 인페이지 광고는 콘텐츠 내부나 콘텐츠 사이에 배치될 수 있지만, 페이지 구조와 콘텐츠 양에 영향을 받는다.
- 광고가 표시되지 않는 원인에는 계정/정책 문제뿐 아니라 광고 코드 문제, ads.txt 문제, 크롤러 접근 문제, 수요 부족, 사이트 구조 문제가 포함된다.
- 광고를 콘텐츠처럼 보이게 하거나, 사용자가 광고와 콘텐츠를 혼동하게 만드는 배치는 위험하다.

참고한 공식 문서:

- Google AdSense 고객센터 - 자동 광고 정보: https://support.google.com/adsense/answer/7478040
- Google AdSense 고객센터 - 자동 광고 설정: https://support.google.com/adsense/answer/9261307
- Google AdSense 고객센터 - 광고가 사이트에 게재되지 않는 문제 해결: https://support.google.com/adsense/answer/1208336
- Google AdSense 고객센터 - ads.txt 문제 해결: https://support.google.com/adsense/answer/7532444
- Google Publisher Policies: https://support.google.com/publisherpolicies/answer/10502938

## 5. 광고 slot prop 반영 구조는 수정 완료

대상 파일: `components/AdSense.tsx`

기존에는 컴포넌트가 `slot` prop을 받지만 실제 `data-ad-slot`에는 전달받은 값을 쓰지 않고 `3446997082`만 고정 출력했다. 이 경우 상단 광고, 중단 광고, 사각형 광고의 성과를 애드센스에서 분리해 보기 어렵다.

조치 완료: `data-ad-slot`이 `slot` prop 기반으로 동작하도록 수정했다.

단, 사이트 여러 곳에 들어간 slot 값은 실제 애드센스 광고 단위라기보다 placeholder로 보인다.

예:

- `components/BlogPostPage.tsx:270` `slot="1234567890"`
- `components/BlogPostPage.tsx:305` `slot="1122334455"`
- `app/[locale]/saju/page.tsx`, `app/[locale]/mbti/page.tsx`, 결과 페이지 등에서도 여러 slot 값을 넘김.

안전 처리: 위 placeholder 값들은 그대로 실송출에 쓰면 광고가 끊길 수 있으므로, 현재는 기존 실광고 slot `3446997082`로 fallback되도록 했다. 추후 애드센스에서 발급한 실제 slot ID로 교체하면 그 값이 그대로 `data-ad-slot`에 반영된다.

판단: 구조 수정 완료. 실제 위치별 리포팅 분리는 애드센스에서 발급한 실 slot ID 교체가 남아 있음.

## 8. 본문 시작 전 요소가 많아 광고와 콘텐츠 사이의 맥락이 약함

현재 광고는 본문 바로 앞에 있기는 하지만, 그 앞에 콘텐츠성 요소가 많다.

- CTA
- breadcrumb
- 제목
- 이미지
- Editorial Review
- 목차

이 구조에서는 광고가 "본문을 읽는 흐름 중간"에 자연스럽게 끼는 것이 아니라, 본문에 들어가기 전에 여러 장식/안내 요소 뒤에 붙는다. Google의 인페이지 광고 최적화 관점에서는 실제 텍스트 콘텐츠 흐름 사이의 광고 후보가 더 강할 수 있다.

특히 글 상단 광고가 잘 안 보인다고 느낀다면, 원인은 "광고가 없는 것"이 아니라 "광고 후보가 콘텐츠보다 앞이면서도 화면상으로는 너무 아래인 애매한 위치"일 가능성이 높다.

판단: 중간 중요도.

## 9. ads.txt와 crawler 접근은 현재 큰 문제로 보이지 않음

확인 파일:

- `public/ads.txt`
- `app/robots.ts`

`ads.txt`는 정상적인 형식이다.

```txt
google.com, pub-2524681039359256, DIRECT, f08c47fec0942fa0
```

`robots.ts`도 일반 결과 페이지 일부를 막고 있지만, `Mediapartners-Google`은 별도 허용한다.

```ts
{
  userAgent: 'Mediapartners-Google',
  allow: '/',
}
```

따라서 현재 확인 범위에서는 "애드센스 크롤러가 막혀서 상단 광고가 안 뜬다"는 쪽은 1차 원인으로 보기 어렵다.

판단: 문제 가능성 낮음.

## 10. 자동 광고만으로 상단 노출을 기대하면 안 됨

사이트에는 수동 AdSense 컴포넌트가 있고, 동시에 애드센스 스크립트도 전체 레이아웃에서 로드된다. 만약 AdSense 계정에서 자동 광고가 켜져 있다면 Google이 추가 위치를 판단할 수 있다.

하지만 자동 광고는 운영자가 원하는 위치에 고정으로 "상단 광고"를 보장하지 않는다. 특히 페이지 상단에 이미 CTA, 이미지, 목차, 수동 광고 후보가 있으면 자동 광고가 상단을 피하거나 다른 위치에 넣을 수 있다.

즉 "글 상단에 잘 안 걸림"은 자동 광고 로직상 자연스러운 결과일 수 있다. 상단 고정 수익을 원하면 자동 광고 기대보다 수동 광고 위치와 로딩 안정성을 먼저 정리해야 한다.

판단: 참고 중요.

## 12. 우선순위별 권장 조치

아래는 현재 조치 상태와 남은 운영 확인 항목이다.

### 1순위: 상단 광고의 실제 위치 재검토

상단 광고는 목차 뒤에서 대표 이미지 바로 아래로 이동했다. 이제 운영 환경에서 모바일 첫 화면 기준으로 실제 광고 노출 위치를 확인해야 한다.

추천 판단 기준:

- 모바일 390px 폭에서 첫 광고가 첫 화면 안에 들어오는가?
- 제목과 대표 이미지 다음 바로 광고가 필요한가?
- 대표 이미지 직후 광고와 본문 첫 1~2문단 뒤 광고 중 어느 쪽의 RPM/CTR/체류 품질이 더 나은가?
- CTA를 광고보다 먼저 둘 이유가 수익 관점에서 충분한가?

### 2순위: 광고 숨김 타이머 제거 완료

2.5초 안에 iframe이 없다고 광고를 숨기던 fallback timer는 제거했다. 운영 환경에서는 이후에도 `data-ad-status="unfilled"` 비율과 실제 fill rate를 확인해야 한다.

### 3순위: 광고 slot 운영 방식 정리

`AdSense` 컴포넌트는 `slot` prop을 사용할 수 있게 수정했다. 다만 실제 위치별 리포팅을 하려면 애드센스에서 발급한 실 slot ID를 각 위치에 넣어야 한다.

권장 방향:

- 상단 글 광고용 slot
- 본문 중단 광고용 slot
- 하단/관련글 근처 광고용 slot
- 결과 페이지 광고용 slot

이렇게 나누면 어느 위치가 실제로 수익을 내는지, 상단만 fill rate가 낮은지 확인할 수 있다.

### 4순위: 광고 라벨 깨짐 수정 필요

한국어 라벨은 현재 `광고`로 정상 확인된다.

### 5순위: CTA와 광고의 우선순위 결정

글 상세 최상단 CTA는 제거했다. 이후에는 광고 수익이 더 중요한 글 페이지와 분석 도구 전환이 더 중요한 랜딩/분석 페이지를 분리해서 운영하는 것이 낫다.

## 13. 결론

현재 상태에서 "글 상단에 광고가 잘 안 걸린다"는 체감은 충분히 설명된다.

가장 직접적인 원인은 애드센스 계정 문제가 아니라 사이트 내부 배치와 렌더링 로직이었다. 2.5초 숨김 타이머, slot prop 미반영, 상단 광고 위치 문제를 수정했다.

심사관 관점에서 승인 자체를 흔들 정도의 큰 문제는 현재 확인 범위에서 보이지 않는다. 다음 우선순위는 운영 데이터로 대표 이미지 직후 상단 광고의 fill rate, RPM, CTR, 모바일 첫 화면 노출 여부를 확인하는 것이다.
